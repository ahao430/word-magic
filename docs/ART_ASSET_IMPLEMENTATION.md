## 3. 盘点发现的质量问题（关键结论）

### 3.1 半透明导出缺陷（已修复）
8 张地块的 Alpha 全部落在 224~254，**没有任何全不透明像素**——导出时被全局降低不透明度，
在引擎深色背景上会整体发虚。地面 Tile 必须全不透明。

### 3.2 烘焙棋盘格陷阱（未修复，仅限参考件）
以下文件的"透明棋盘格"是**烤进 RGB 像素的图案，不是真透明**，绝不能当作透明背景直接使用：
- 瀑布 9 帧与 3×3 图集：Alpha 全 255 形同虚设，画面右侧/顶部烤入白灰棋盘格（像素级验证：
  主色 252/236/230/244 交替），且构图偏左。
- `forest_water_reference.png`：RGB 无 Alpha 通道，棋盘格直接绘制在像素里。
- `forest_water_static_reference.png`：虽有 Alpha 通道，但 95.6% 像素为半透明噪声，
  烤入背景依然可见。**"有 Alpha 通道" ≠ "真透明"。**
- `concept_atlases/` 中多张图集存在同样问题。

### 3.3 网格对齐
- ✅ 仅 8 张地块（32×32）与 138×70 图集对齐 32px 网格（图集带 2px 沟槽，直接导入 Godot
  Atlas 需配置 separation=2）。
- ❌ 所有 1536×1024 参考集：尺寸能被 32 整除，但**内容不在 32 网格上**，不可直接切图。
- ❌ 瀑布帧 439×390 不对齐任何标准网格。

### 3.4 接缝（无缝平铺）
对 7 张地块做对边像素比对：**无一可无缝平铺**（不匹配 19~31/32 像素）。
当前地块只可作原型占位；生产级无缝地形集是后续工作（§5）。

### 3.5 其他
- `dirt_grassy_edge` 是单张"林间空地"样本，**不是**过渡 Tile 集；其右边缘有 39 像素浅色
  背景污染（已修补，见 §4）。
- 原 `word_magic_transitions_v1/` 的 README 与包内容错位（README 描述的参考图在仓库根目录），
  重组时已将 README 与参考图归位到 `forest_transitions_ref/`。
- 瀑布动画的动效逻辑正确：岩石/植物完全静止对齐，仅水柱高光、泡沫、涟漪变化——是理想的
  动作参考；但它是整幅插画，不是上/中/下模块化瀑布 Tile。

## 5. 生产路线（后续阶段，按顺序）

依据各参考包 README 与盘点结论，重制路线：

1. **地形过渡集**：草地↔泥土过渡（中心、四直边、四外角、四内角），32×32 严格网格，
   在 Godot 中验证全部相邻组合。参考 `forest_transitions_ref/`。
2. **水域系统**：静态水面 Tile + 河岸自动瓦片（直边/内角/外角/孤角），河流弯道做模块化
   大件而非硬塞单格。参考 `forest_water_ref/` 两包。
3. **瀑布模块化**：拆分为顶部/中部/底部三段 + 泡沫动画帧，静态件先通过平铺验证再做动画。
   参考瀑布动画包的动效节奏（约 180ms/帧 ≈ 5.56 FPS）。
4. **物件层**：岩石、荷叶、芦苇、溅射等导出为独立透明 PNG（先解决真透明，再谈切图）。
5. 每一步都必须在 Godot 测试图（建议 10×10 拼块）中以 Nearest 过滤、关 Mipmap 验证。

**通用红线**（承接盘点结论）：
- 禁止把参考集按猜测的 32×32 网格直接切图。
- 禁止把棋盘格图案误当透明背景；一切素材入库前先做 Alpha 程序化检查。
- 禁止未经检查就把非 32×32 素材缩放为 32×32。
- 原始件只增不改；所有加工发生在生产副本目录。
